# Egern 排障指南

排障顺序是“先恢复，再定位，再重新灰度”。如果新 Profile 影响基本联网，立即回滚：断开新 Profile，选择旧 Profile并启动；确认中国流量直连和境外流量代理恢复后再收集非敏感诊断。不要删除或覆盖旧 Profile。

## 1. Sub-Store 生产器失败

先读错误类型，不要绕过校验：

- `produceArtifact` 或 producer 不可用/unavailable：当前 Sub-Store 运行环境没有提供受支持的生产器入口。确认使用的是 File 任务和完整生成器，而不是节点操作符。
- producer 拒绝/rejected：输入类型、参数或调用约定不符合契约。逐字核对 `output`、`type` 与集合名称。
- 返回非数组/non-array：集合 API 没有返回节点数组，检查任务是否真的指向 collection。
- 空数组/empty 或空结果：上游集合没有可见节点，先单独预览已有集合。

如果集合预览有节点，但 File 输出仍是 `// 填入文件内容` 或空内容，通常是旧外置脚本把 Sub-Store 注入的 `undefined` 可选字段误判为畸形节点。先刷新到 Pages 的最新 `current/egern/scripts/egern-node-generator.js`，再重新预览 `egern-nodes`；不要手工在编辑器里补 `dns: {}`，那不是节点文件。

校验错误、空结果和全部节点不可渲染仍然 fail-closed（失败即停止）；renderer 无法表示的单个节点会跳过并计入 `renderFailures`，不会伪造字段。不得关闭、绕过或削弱 fail-closed 校验来得到“看似成功”的空配置。

## 2. 没有兼容节点

如果诊断显示“没有兼容节点”或“无兼容节点”，比较 `total`、`accepted` 和每类 excluded 排除原因：

- 名称冲突或重名：不同节点被规范化为同一名称。到私密源中改成唯一名称，再重跑任务。
- fingerprint/指纹冲突：同一端点或身份重复。确认是否重复订阅，不要盲目保留多个副本。
- Egern 不支持的协议：renderer 无法表示的节点会跳过并计入 `renderFailures`；如果全部节点都被跳过，任务会失败。不要把协议字段伪装成其他类型。
- 字段错误、畸形或不完整：回到源订阅修正地址、端口、认证或传输字段，真实值不要贴进 Issue。

`accepted` 必须至少为 1；否则不要导入 Profile。

## 3. 私密节点 URL 失败

只在自己的 Sub-Store 与 Egern 内检查真实地址：

- `401` 或 `403`：认证、权限或私密分享策略拒绝请求。重新生成自己的授权地址，不要公开它。
- `404`：File 任务名称、路径或分享对象不存在。确认检查的是 `egern-nodes` 输出，不是 Profile 输出。
- `TLS` 失败：检查系统时间、域名与证书链。不得关闭或跳过证书验证/TLS 验证，也不要安装来历不明的 CA。
- URL 可达但没有节点：确认响应是节点文件而不是登录页、HTML 或回显输入；比较任务预览的 `accepted`。

## 4. Profile 可导入但主组为空

如果 Egern 接受配置，但 `🚀 节点选择` 主组为空：

1. 独立打开节点 File 的非敏感诊断，确认有接受节点。
2. 检查 Profile 中节点挂载 URL 是否仍是占位域名。
3. 检查名称冲突、fingerprint 指纹冲突、`renderFailures` 协议计数，以及字段畸形、不完整或错误。
4. 刷新私密节点任务，再刷新 Profile；不要用删除旧 Profile 代替修复。

公开规则文件与私密节点文件要分别、独立诊断。规则下载成功不能证明节点订阅成功，反之亦然。

## 5. DNS 或规则异常

- DNS 完全失败：分别检查 bootstrap 能否解析上游域名，以及 upstream 是否可达；先排除当前网络门户认证。
- 国内外分流异常：确认 rule-set/规则集下载成功、顺序没有被手工改写，并检查命中的最后规则。
- 国内 App 偶发变慢、切换开关后暂时恢复：先确认 `DomesticCore`、`DomesticGame`、`SteamCN` 在明确境外规则之前直连，`ChinaIP` 与可解析的 `GEOIP CN` 在最终代理之前。稳定/速度 DNS 模式应使用同一 `channel` 的 `DomesticCore` 转发到国内 DNS；不应再看到 `ChinaMax_Domain`。若 DNS 失败，未命中流量落入 `🚀 节点选择` 是预期的 fail-safe，不要通过恢复大分类包解决。
- 只有公开规则失败：测试 `🧭 DNS 与规则下载` 的代理优先路径和直连回退，不要改私密节点 URL。
- 只有节点失败：重跑私密节点 File，不要把公开规则刷新当成节点修复。

节点挂载正常周期是 6 小时；公开规则正常周期是 24 小时。修改来源或参数后可以主动重跑对应任务，但不要误判两者为相同的刷新周期。

## 6. QUIC、UDP 与网络切换

- QUIC 站点异常：记录当前模式和是否回退到 TCP，再分别验证允许、代理阻止、全部阻止；页面成功不代表一定使用 HTTP/3。
- UDP 应用异常：用一个明确依赖 UDP 的非敏感应用验证，并检查所选节点是否支持 UDP。不要通过关闭安全校验来掩盖问题。
- Wi-Fi 正常而蜂窝异常，或反之：分别检查 DNS、IPv6、网络权限与节点连通性，保持一次只改一个变量。

## 7. IPv6 平台差异

- Intel Mac 默认 `ipv4-only`，iPhone、iPad 默认 `auto`；默认值不是实际验证。每台适用设备仍要在 IPv4 可用网络验证 `ipv4-only`，并在确认有 IPv6 的网络验证 `auto` 的真实 IPv6 路径。
- ISP/运营商或当前网络不提供 IPv6 时，标为“未覆盖/不可验证”，不得把页面可打开或 `auto` 已启用当成通过，也不得假设网络有 IPv6；换到可验证网络后重新灰度。
- 在 IPv6-only 和双栈网络分别观察 DNS 与连接，不要照搬其他设备的结果。
- IPv4/IPv6 变化引发失败时，保留网络类型、时间和非敏感错误码；不要公开地址、节点或订阅。

## 8. 客户端链路失败

默认关闭链路。如果已明确开启：

- 检查入口和落地节点都存在、协议受支持且名称唯一。
- 检查生成的落地 clone 的 `prev_hop` 精确引用 `🔗 入口节点`，没有悬空或反向引用。
- SSH 场景要检查认证与服务器策略；clone/克隆节点后必须重新核对入口、落地关系，不能依赖旧名称。
- 缺少入口或落地、引用错误或来源不合法时，关闭此次变更并回到旧 Profile；不要强行生成。

## 9. 缓存与陈旧输出

节点超过 6 小时未更新时，重跑 `egern-nodes` 并检查其私密 URL；规则超过 24 小时未更新时，检查公开规则 URL 和下载策略。Profile 默认省略 `auto_update`，参数变化后需要重新运行或刷新私密 Sub-Store Profile File 任务，再在 Egern 手动更新远程 Profile。不要自行添加空的 `auto_update: {}`，Egern 会报缺少 `url`。

## 10. 安全回滚与求助

以下情况立即回滚：无法基本联网、DNS 持续失败、意外直连、策略组为空、节点或规则来源不可验证、证书错误、链路引用悬空。按固定顺序断开新 Profile、选择旧 Profile、启动旧 Profile，然后验证中国流量直连和境外流量代理。

求助时只提供 Egern 版本、设备类型、网络类型、参数枚举、错误类别、`total`/`accepted` 数字及已脱敏的排除计数。不得公开、发布、粘贴或上传私密 URL、订阅 URL、Profile URL、节点地址、认证信息或完整配置；截图和日志也要先脱敏。不得启用 MITM 或 HTTPS 解密，不得安装 CA 证书，也不得关闭或跳过 TLS 验证。
