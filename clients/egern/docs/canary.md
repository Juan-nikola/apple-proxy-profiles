# Egern 灰度与回滚指南

发布顺序固定为：1. Intel Mac；2. iPhone；3. iPad。一次只验证一台设备，不得同时更新。任一检查失败就停止，后续设备保持原样。

## 每台设备开始前的共同门槛

1. 保留旧 Profile，不要覆盖或删除；给新 Profile 使用明显不同的名称。
2. 记录当前选中的策略和节点，以及测试时间、网络和 Egern 版本。
3. 暂停可能自动传播 Profile 的 iCloud 或其他同步，确保只影响当前设备。
4. 私密节点 URL 与公开规则 URL 必须分别、独立检查：确认各自可达、内容类型正确，真实地址不出现在截图或日志中。
5. 查看生成诊断，比较 `total`（归一化总数）与 `accepted`（接受数），解释排除原因；`accepted` 至少为 1。
6. 检查所有引用：不得有悬空引用，也不得有空的必需策略组。

## 每台设备都要执行的功能检查

### 策略组

- `🚀 节点选择` 存在并能选择一个实际可用节点。
- 境外规则是代理优先，最终能进入 `🚀 节点选择`；国内规则是直连优先，最终能进入 `DIRECT`。
- `🧭 DNS 与规则下载` 是代理优先，并保留直连回退。
- 按当前 `blockMode` 检查安全组：平衡模式至少覆盖 `☣️ 安全威胁` 与 `🧱 常见广告`；严格模式还应观察跟踪拦截。
- 需要的 `🤖 AI 专用`、`🎮 游戏连接` 与 `⬇️ 下载/P2P` 均存在且可以选择策略。

### 实际流量

- 局域网或路由器管理页可以直连访问。
- 中国网站或应用命中 `DIRECT`。
- 境外网站命中 `🚀 节点选择`，并能观察到实际代理节点。
- AI 服务按 `🤖 AI 专用` 策略运行；广告或安全规则产生符合预期的阻止；游戏和下载/P2P 各做一次非敏感测试。
- DNS 解析正常，分别观察 bootstrap 与 upstream；规则刷新和节点刷新分别成功。
- 在移动设备上分别测试 Wi-Fi 与蜂窝/移动网络；切换网络后再次确认 DNS、规则和节点。

### IPv6、QUIC 与链路

- macOS 默认是 `ipv4-only`；iPhone 默认是 `auto`；iPad 默认也是 `auto`。不要用一台设备的默认值推断另一台。
- QUIC 只按可观察结果验证：依次比较 `allow`、`proxy-block`、`all-block`，记录连接成功、回退或阻止。HTTP/3 不保证一定被目标站点使用，因此不得仅凭页面能打开就假设命中 HTTP/3。
- 默认保持 `clientChain=off`。若以后改为 on，必须同时存在合法、兼容的入口与落地节点，并确认入口的 `prev_hop` 精确指向落地；任何缺失都应停止生成。

## 每台设备必做的真实回滚演练

每台设备都必须实际执行回滚，不接受只阅读步骤或仅确认“旧配置还在”：

1. 断开新 Profile。
2. 选择旧 Profile。
3. 启动旧 Profile。
4. 用旧 Profile 检查一个中国站点是否直连/DIRECT，再检查一个境外站点是否正常代理或进入 `🚀 节点选择`。
5. 只有回滚成功后才可返回新 Profile 并继续本机验证；若回滚失败，保留现场并停止发布。

## 1. Intel Mac

先在 Intel Mac 导入 macOS 私密 Profile。完成共同门槛、全部功能检查与真实回滚演练，至少经过一次规则刷新和一次节点刷新观察窗口。确认没有 DNS 泄漏迹象、异常循环或意外直连后，记录通过结果。

Intel Mac 出现任一不一致时，立即回滚，并停止 iPhone、iPad 和全部后续设备；它们保持原样。

## 2. iPhone

只有 Intel Mac 全部通过后，才在 iPhone 导入手机 Profile。重复完整检查，不得复用 Mac 的结论。重点在 Wi-Fi 与蜂窝网络间切换，保持 IPv6 `auto`，并实际完成旧 Profile 回滚演练。

iPhone 出现任一不一致时，立即回滚，并停止 iPad 与后续设备；Intel Mac 的已验证状态不要顺手改动。

## 3. iPad

只有前两台都通过后，才在 iPad 导入平板 Profile。再次独立完成全部检查、Wi-Fi/蜂窝（若设备支持）测试、IPv6 `auto` 观察和真实回滚演练。iPad 通过后，三设备灰度才完成。

## 立即停止的条件

出现以下任何一项都立即回滚：`accepted` 为 0、必需策略组为空、引用悬空、私密节点或公开规则无法独立下载、国内流量意外代理、境外流量意外直连、DNS 持续失败、旧 Profile 无法恢复。不要为了继续发布而关闭证书验证/TLS 验证、启用 MITM、删除旧 Profile，或绕过 fail-closed 校验。
