# Shadowrocket 多平台配置生成器设计

日期：2026-07-24  
状态：已由用户批准  
目标客户端：最新稳定版 Shadowrocket，iPhone、iPad、Intel/Apple Silicon Mac；以后扩展 Apple TV

## 1. 目标

建立独立项目 `shadowrocket-profile`，为完全不了解 Shadowrocket 配置语法的用户提供可长期维护的 Sub-Store 生成器、自动验证、脱敏诊断和零基础部署手册。

系统默认实现：

- 中国大陆域名和 IP 直连，境外流量代理。
- 未被域名规则识别的请求解析真实 IP；中国 IP 直连，其他 IP 或无法判断的请求进入主代理组。
- 节点、策略组、DNS、IPv6、QUIC、广告拦截、服务分流和多平台配置均由生成器管理。
- 日常增加机场或自建节点只修改 Sub-Store 来源，不手工编辑 Shadowrocket 配置。
- 节点订阅与配置 Profile 分离，避免节点凭据与规则配置耦合。

## 2. 范围与非目标

### 2.1 本期范围

- 独立 Git 项目、构建脚本、测试、示例、部署和维护文档。
- 一份规范化 Shadowrocket 节点订阅。
- macOS、iPhone、iPad 三份平台 Profile。
- Apple TV 参数和结构预留，但不作为首轮部署验收对象。
- Snell、VLESS（含 Reality）、Hysteria2、Shadowsocks/2022 为重点协议；同时允许 Sub-Store 提供其他 Shadowrocket 支持的协议。
- 机场、自建、Realm 转发、服务端链式代理和客户端链式落地的明确分类。

### 2.2 非目标

- 不修改现有 sing-box 项目。
- 不修改或加固当前公网 Sub-Store 服务；管理界面无认证的风险只记录，不在本期处理。
- 不启用 HTTPS 解密、不安装根证书、不修改请求正文。
- 不承诺仅靠代理改变平台显示的评论地区；账号、手机号、GPS、缓存和平台风控可能继续影响结果。
- 不伪造 GPS、不绕过服务条款、不自动让机场承担 P2P。
- 不把 Shadowrocket 的客户端设置伪装成配置参数；日志保留、始终连接和 iCloud 同步等通过部署手册设置。

## 3. 总体架构

数据流分为两条：

1. Sub-Store 来源 → 节点规范化脚本 → `shadowrocket-nodes` 远程节点订阅。
2. 平台和功能参数 → 配置生成器 → macOS、iPhone、iPad 各自的远程配置 Profile。

每台设备初次导入：

- 共同的 `shadowrocket-nodes` 节点订阅。
- 与平台匹配的一份配置 Profile。

节点订阅每 6 小时更新。配置和远程规则每天更新。节点凭据只存在于私密节点订阅链路，不嵌入公开规则源码、示例、日志或设计文档。

### 3.1 实现基线

- 使用 Node.js 22 或以上版本和 ESM JavaScript。
- 使用 Node 内置测试运行器完成单元与回归测试。
- 使用 esbuild 将 Sub-Store 运行时代码打包为单文件。
- 运行时不从 npm 加载依赖；第三方规则只通过声明式目录引用。
- 源码分模块维护，`dist/` 只存放可重新构建的产物，不手工修改。

## 4. Sub-Store 来源约定

来源显示名采用大小写不敏感的前缀：

| 前缀 | 含义 | 客户端行为 |
|---|---|---|
| `[机场]机场名字` | 机场订阅 | 普通节点；不进入 P2P 候选 |
| `[自建]节点类型` | 普通自建节点 | 普通节点；可进入 P2P 和入口候选 |
| `[realm] XXX` | Realm 已在服务器端完成转发 | 普通现成节点，不自动视为客户端落地 |
| `[链式代理] XXX` | 3x-ui 等已在服务器端完成链路 | 普通现成节点，不再套客户端链路 |
| `[落地] XXX` | 明确允许由 Shadowrocket 通过入口连接的落地 | 保留普通节点，并按参数生成客户端链式副本 |

输出时将标签统一显示为 `[机场]`、`[自建]`、`[Realm]`、`[链式代理]`、`[落地]`。没有标签的来源不会被丢弃，但会产生诊断警告；其节点仍可进入主组和地区组，不进入需要明确来源授权的 P2P 或链式组。

## 5. 节点规范化

处理顺序固定为：

1. 读取来源元数据和原始节点。
2. 校验协议必填字段、TLS 形状和 UDP 能力。
3. 排除公告、套餐、流量、到期时间和缺少必要字段的伪节点。
4. 对完整规范化配置生成内存指纹，删除完全相同的重复节点。
5. 识别国旗、地区和来源，生成稳定显示名。
6. 输出节点订阅和不含敏感字段的统计结果。

### 5.1 地区识别

- 节点名已有国旗时不重复添加。
- 已有国旗是最高优先级；与地区文字冲突时仍按国旗分类。
- 多个国旗时按最左侧可识别国旗分类，同时输出冲突警告，不删除原名。
- 完整覆盖 ISO 3166-1 的 249 个国家和地区国旗；中东和大洋洲归亚太，俄罗斯归欧洲，美洲包含加勒比，非洲和南极洲归其他。
- 无国旗时依次使用国家/地区中英文、常见城市、机场代码和缩写推断。
- 无法可靠识别时不猜测，进入 `🌐 其他/未分类`。

### 5.2 稳定命名和去重

显示名形状为：

```text
{国旗} {统一来源标签} {原节点名}
```

已有国旗只保留一份。完全相同的节点只保留一个；同名但参数不同的节点全部保留，并通过来源标签和稳定短序号消除重名。序号来源于稳定身份，不因订阅顺序改变。

指纹可在内存中使用服务器、端口、协议、认证和安全参数判断完全相同，但任何日志和报告都不得输出指纹输入、服务器、密码、PSK、UUID、私钥或订阅 URL。

### 5.3 协议和安全

- 重点验证 Snell、VLESS/Reality、Hysteria2、Shadowsocks/2022。
- 保留每个节点已有的证书校验、SNI、指纹、混淆和 UDP 设置。
- 不把某个 Hysteria2 节点的 `allowInsecure` 扩散到其他节点。
- 缺少有效证书、指纹或明确跳过验证设置的 TLS 节点给出警告。
- 游戏候选只包含明确支持 UDP 的节点；不能仅凭协议名字猜测。

## 6. 策略组设计

### 6.1 主组和地区组

可见主组：

- `🚀 节点选择`
- `🌏 亚太`
- `🌍 欧洲`
- `🌎 美洲`
- `🌐 其他/未分类`
- `🏠 自建节点`
- `🏢 机场节点`
- `↪️ Realm 转发`
- `⛓️ 链式代理`
- `🎯 客户端落地`

`🚀 节点选择`包含全部自动、全部故障转移、当前有节点的地区组，以及由 `subscriptionName` 命名的全节点订阅入口。每个洲组包含本洲自动、本洲故障转移和本洲具体节点。地区组顺序固定为亚太、欧洲、美洲、其他；没有节点的地区组不生成。

不生成国家策略组。节点在洲组内按国旗、来源和稳定名称排序，避免 Shadowrocket 代理组页面出现大量平铺国家组。

自动测速和故障转移辅助组使用 `hidden=1` 隐藏，但仍可由上层组选择。自动组只包含具体节点，不嵌套其他自动组。

### 6.2 服务组

可见服务组覆盖：

- `🤖 AI 专用`
- GitHub
- YouTube、Netflix、Disney+、Spotify、国际媒体
- Telegram、海外社交、TikTok
- Apple、Microsoft
- 哔哩哔哩、抖音、小红书、微博
- 游戏平台、游戏连接
- 下载/P2P
- `🧭 DNS 与规则下载`

默认行为：

- AI、GitHub、YouTube、流媒体、Telegram、海外社交、TikTok、游戏平台网页默认代理。
- Apple、Microsoft 默认直连，但可手动选择代理。
- 哔哩哔哩、抖音、小红书、微博分别有独立策略组，默认直连，可选择当前 `🚀 节点选择`出口或全节点订阅中的具体节点。
- AI 专用组直接列出全部已勾选节点，用户可手动选择任意具体节点，因此 AI 可与主线路使用不同出口。
- 原本允许任意选节点的普通业务组保留由 `subscriptionName` 命名的全节点订阅入口。
- 下载/P2P 默认直连，手动候选只包含自建、Realm 转发和服务端链式节点，不含机场。
- 游戏实时连接默认直连，候选只包含明确支持 UDP 的节点。

### 6.3 广告与安全热切换

三个可见层级分别选择拦截或放行：

- `☣️ 安全威胁`
- `🧱 常见广告`
- `🕵️ 严格跟踪`

模式映射：

- 关闭：三层全部放行。
- 仅安全：只拦截安全威胁。
- 均衡：拦截安全威胁和常见广告。
- 严格：三层全部拦截。

`blockMode` 只设置首次生成的默认选择，默认 `balanced`。用户以后可在客户端即时切换三个组，不重新生成配置。更新后是否保留客户端选择属于灰度验收项。

### 6.4 客户端链式代理

- `[realm]` 和 `[链式代理]` 始终是已经配置好的普通节点。
- `🔗 入口节点` 只包含适合作为第一跳的普通节点和分组，不包含服务端链式节点。
- `[落地]` 节点保留一份普通节点；当 `clientChain=on` 时，另外生成带 `🔗` 前缀、通过 `🔗 入口节点` 连接的副本。
- 默认 `clientChain=off`，不生成自动链式副本，只保留说明和相关分类。
- 不支持代理链或 UDP 行为不明确的协议组合不生成链式副本。
- 入口丢失时必须关闭连接，不能跳过入口直连落地。

## 7. 分流顺序

Shadowrocket 从上到下首次命中即停止，规则顺序固定：

1. 私有 IPv4/IPv6、`.local`、mDNS、Bonjour、AirPlay、HomeKit、NAS、打印机和路由器管理直连。
2. 用户自定义规则：拦截 → 直连 → 主代理 → AI。
3. 安全威胁、常见广告、严格跟踪三层规则。
4. 哔哩哔哩、抖音、小红书、微博独立策略组。
5. AI。
6. GitHub。
7. YouTube、流媒体、Telegram、海外社交、TikTok 等海外服务。
8. Apple、Microsoft。
9. 游戏平台、游戏连接和下载/P2P。
10. 已知中国域名直连。
11. 解析未识别域名和直接 IP 流量；`GEOIP,CN` 直连。
12. `FINAL,🚀 节点选择`。

AI 和 GitHub 必须早于 Microsoft。四个国内平台必须早于通用中国域名直连规则，才能让用户临时切换出口。

全球 CDN、共享云和 Anycast 可能造成 GeoIP 误判。长期纠错写入源码中的四个简单列表：

- `CUSTOM_BLOCK`
- `CUSTOM_DIRECT`
- `CUSTOM_PROXY`
- `CUSTOM_AI`

用户列表优先于公共规则，并接受格式、重复和交叉冲突检查。

## 8. DNS、IPv6 和 QUIC

### 8.1 DNS 模式

`dnsMode` 支持：

- `stable`：默认；国内加密 DNS 直连，境外加密 DNS 经代理，超时后回退。
- `privacy`：尽量使用加密 DNS，境外查询强制经代理。
- `speed`：优先系统或国内 DNS，接受较弱的隐私和抗污染能力。

`chinaDns` 支持 `alidns`、`dnspod`、`system`。  
`globalDns` 支持 `cloudflare`、`google`、`quad9`。

代理 DNS 必须有无循环的引导解析路径。已知境外服务在域名规则阶段进入代理，未知域名在 `GEOIP,CN` 阶段触发真实 IP 判断。针对已知污染或劫持 IP 的纠错规则必须早于 `GEOIP,CN`。

DNS 模式和提供商不是策略组热切换；修改 Sub-Store 参数、重新生成并更新 Profile 后生效。

### 8.2 IPv6

`ipv6Mode` 支持：

- `auto`：默认；网络具备可用 IPv6 时保留，所有 IPv6 流量继续参与直连或代理规则。
- `ipv4-only`：仅作为兼容或故障排查模式。

私有和链路本地 IPv6 直连，其他 IPv6 不得绕过 `FINAL`。配置必须验证 IPv4-only、双栈和 IPv6-only 网络的行为。

### 8.3 QUIC

`quicMode` 支持：

- `allow`：默认，允许应用 QUIC/UDP。
- `proxy-block`：阻止走代理的应用 UDP/443，使应用尝试回落 TCP。
- `all-block`：阻止全部应用 UDP/443，仅用于排障。

应用 QUIC 开关与 Hysteria2/TUIC 等节点的底层传输分开验证，不得把切换应用 QUIC 等同于禁用代理协议。

## 9. 平台参数

配置入口至少接受：

```text
output=nodes|config
type=collection
name=shadowrocket-sources
platform=iphone|ipad|macos|appletv
subscriptionName=Shadowrocket-Nodes
dnsMode=stable|privacy|speed
chinaDns=alidns|dnspod|system
globalDns=cloudflare|google|quad9
blockMode=balanced|security|strict|off
quicMode=allow|proxy-block|all-block
ipv6Mode=auto|ipv4-only
autoGroupMode=auto|full|balanced|minimal
clientChain=off|on
```

参数值未知或缺少必填项时直接报错，不静默使用猜测值。

平台预设：

- macOS：完整规则和诊断，作为首台灰度设备；Intel 和 Apple Silicon 共用语义。
- iPhone/iPad：规则能力相同，降低后台测速并发和频率。
- Apple TV：以后启用，默认精简测速、局域网优先和较少日志。

`autoGroupMode=auto` 为默认值：有效节点不超过 30 个时采用完整测速，31–100 个时采用均衡测速，超过 100 个时采用精简测速。手动指定 `full`、`balanced` 或 `minimal` 可覆盖阈值。任何模式都保留全部手动节点，只调整后台测试组和频率。

## 10. 客户端设置

以下项目写入逐台部署手册，不假装由 Profile 自动完成：

- Shadowrocket 更新到 App Store 最新稳定版。
- 始终连接，并在设备重启或异常断开后自动恢复。
- 完整连接、规则命中和 DNS 日志；自动删除 7 天前日志。
- 关闭 Shadowrocket iCloud 节点自动同步，Sub-Store 是唯一节点来源。
- Shadowrocket 运行时避免叠加 iCloud 私密转送；断开后可恢复系统行为。
- 保持 HTTPS 解密关闭。
- 节点订阅每 6 小时更新；配置和远程规则每天更新。

## 11. 远程规则管理

- 使用适配 Shadowrocket 格式、公开许可清晰、持续维护的远程规则集。
- 服务规则通过声明式目录映射到策略组，不在生成器各处硬编码 URL。
- 网络检查验证 HTTP 状态、内容类型、最小条目数和基本格式。
- 记录第三方许可证和来源。
- 运行时下载失败时优先使用 Shadowrocket 上一次可用缓存；首次部署时资源不完整则停止灰度，不覆盖旧配置。

## 12. 失败保护和脱敏

- 输入集合为空、全部节点无效或转换异常时构建失败，不发布空订阅。
- 单个坏节点排除并按协议/原因计数，不输出其名称、地址或凭据。
- 所有策略组引用必须存在，组名唯一，不允许循环、空组或引用被过滤节点。
- 自动和故障转移组没有节点时不生成；上层组使用安全候选。
- 未分类地区不阻断生成，但产生统计警告。
- 客户端链式入口缺失时不生成链式副本。
- 构建输出、测试快照、异常、README、截图和诊断不得包含真实服务器、端口组合、密码、PSK、UUID、私钥、订阅 URL、Profile URL 或 Token。
- 诊断工具只输出平台、节点总数、协议计数、地区计数、来源计数、排除原因计数和规则健康状态。

## 13. 测试设计

### 13.1 单元测试

- 来源标签大小写、统一显示和无标签来源。
- 已有国旗不重复、国旗与文字冲突、多国旗、关键词和机场代码识别。
- 公告过滤、完全重复节点去重、同名不同参数保留、稳定命名。
- Snell、VLESS/Reality、Hysteria2、Shadowsocks/2022 字段保存。
- TLS 警告、UDP 能力和 P2P/游戏/链式候选过滤。

### 13.2 配置测试

- macOS、iPhone、iPad 和预留 Apple TV 的全部参数枚举。
- 未知参数和缺少必填参数失败。
- 所有组引用存在且无环。
- 隐藏辅助组只被有效上层组引用。
- AI、GitHub、Microsoft 和四个国内平台的顺序回归。
- `GEOIP,CN,DIRECT` 位于 `FINAL,🚀 节点选择` 之前。
- 广告三层的四种默认模式。
- DNS 引导无循环，IPv6 不绕过，QUIC 参数映射正确。
- 节点数从少量增长到 100、300 以上时的生成结果和测速负担。

### 13.3 网络和安全检查

- 所有远程规则 URL 可下载且格式正确。
- 规则源突然变空或明显缩小时检查失败。
- 生成物密钥扫描。
- 脱敏夹具覆盖主要协议，不使用真实凭据。

### 13.4 手工灰度

1. 备份 Sub-Store 和三台设备现有可用配置。
2. Intel Mac 导入测试节点订阅和 macOS Profile，不覆盖旧配置。
3. 验证节点更新、国内直连、境外代理、未知域名、AI、GitHub、四个国内平台、DNS、IPv4/IPv6、局域网、日志、广告开关和 P2P/游戏候选。
4. 稳定后导入 iPhone，再导入 iPad。
5. 任一步失败立即切回旧 Profile，使用脱敏诊断定位。

- 在 Shadowrocket 哪里添加节点订阅和配置 Profile。
- 每一步成功时应看到什么。
- Intel Mac 灰度、iPhone/iPad 推广和回滚步骤。
- 日常添加机场、自建、Realm 转发、链式代理和客户端落地。
- 切换 DNS、QUIC、IPv6、广告默认值和测速模式。
- 节点更新失败、规则下载失败、DNS 污染、局域网失效、IPv6 异常、AI 风控和评论地区未变化的排查。
- 如何生成并分享脱敏诊断，以及哪些内容绝不能截图或发送。

另提供一页日常维护速查表，避免用户每次阅读完整手册。

## 15. 验收标准

项目只有在以下条件全部满足时才算完成：

- 自动测试、构建、规则健康检查和密钥扫描全部通过。
- Intel Mac 完成完整灰度并保留旧 Profile 回滚入口。
- iPhone 和 iPad 能从同一节点订阅更新，使用各自平台 Profile。
- 未知中国 IP 直连，未知非中国流量进入主代理。
- 四个国内平台能分别在直连、当前主线路出口和全节点订阅中的具体节点之间切换。
- AI 出口能固定为用户选择的具体节点。
- 广告三层能在客户端即时切换。
- 局域网、AirPlay、HomeKit、NAS 和打印机不被远程代理破坏。
- 日常新增机场不需要修改生成器源码。
- 文档可由不了解 Shadowrocket 语法的用户逐步完成部署和回滚。
