# sing-box 规则下载节点故障转移设计

## 背景

sing-box 在启动时会先初始化远程 rule-set。当前配置把规则下载 HTTP client 指向
`🧭 DNS 与规则下载`，该组默认进入 `⚡ 全部自动`。如果自动组当前选中的节点连接被拒绝、超时或 TLS/握手失败，sing-box 会在规则集初始化阶段直接退出，自动测速来不及切换到下一个节点。

## 目标

- 规则下载遇到节点级网络错误时自动尝试下一个候选节点。
- 覆盖连接拒绝、连接/请求超时、TLS 证书与握手失败等可恢复错误。
- 保留自动测速、手动选择和 DIRECT 备用路径。
- 全部候选失败时返回原始错误与尝试摘要，便于定位真正的网络问题。
- 不改变代理节点本身的协议参数，也不在配置中暴露订阅凭据。

## 方案

sing-box 没有为单个远程 rule-set 暴露“失败后换下一个出站并重试”的配置项，因此不能在生成器里伪造一个不存在的 retry 链。实际采用专用 URLTest 故障转移组：

- 新增隐藏的 `🧭 规则下载故障转移` URLTest 组，直接测试每个具体节点和 DIRECT，而不是再嵌套 `⚡ 全部自动`。
- URLTest 的探测 URL 使用实际规则文件 URL（默认使用 `Hijacking.json`），使“节点能测速”变成“节点能下载规则”。
- `🧭 DNS 与规则下载` 仍是可切换的 selector，默认指向专用故障转移组，并保留 `🚀 节点选择`、`DIRECT` 作为手动备用。
- 当当前节点健康检查失败或连接中断时，URLTest 会选用其他健康候选；全部候选失败时，sing-box 仍会返回原始错误。

对生成器无法控制的 sing-box 内部 HTTP 重试，不伪造一个不存在的协议字段；配置只负责提供实际资源健康检查、稳定的候选拓扑和最后的 DIRECT 兜底。

如果 sing-box 版本不支持在规则集初始化阶段自动重试出站，生成器提供 `ruleDownloadMode=direct` 兼容参数，让 SubStore 任务可以切换为 DIRECT 启动模式；该模式用于网络已能直连 GitHub Pages 的环境。

## 数据流

1. SubStore 文件任务调用当前 sing-box generator，并带 `#noCache`。
2. 生成器创建 `🧭 规则下载故障转移` URLTest 组，逐个检查具体节点和 DIRECT 对规则文件的可达性。
3. 生成器创建 `🧭 DNS 与规则下载` 选择组，默认使用故障转移组，并保留 `🚀 节点选择`、`DIRECT`。
4. 每个远程 rule-set 显式引用 `🧭 规则下载 HTTP`。
5. sing-box 初始化规则集；健康检查选择可下载规则的节点，节点失效后 URLTest 切换到其他候选。
6. 全部候选失败时，日志保留每个候选的最终错误。

## 测试

- 断言默认配置包含专用规则下载 URLTest 组和 selector 默认值。
- 断言专用 URLTest 使用实际规则 URL，并包含具体节点和 DIRECT 候选。
- 断言所有规则集显式引用同一个 HTTP client，且不包含已废弃字段。
- 通过 SubStore 文件端点读取 iPhone 和 macOS 生成结果，确认配置可解析、候选链和 rule-set HTTP client 一致。
