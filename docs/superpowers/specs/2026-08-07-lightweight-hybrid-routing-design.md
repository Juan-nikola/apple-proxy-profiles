# 五客户端轻量混合智能分流设计

## 背景与结论

当前项目为 Shadowrocket、Surge、Egern、Anywhere 和 sing-box 生成节点、策略组与分流规则。实际导入 SFM 的 macOS 配置包含 32 个远程 `source` JSON rule-set、59 个出站和 34 条顶层路由规则。默认远程 JSON 总体积约 27 MB，其中：

- `Advertising_Domain` 约 19 MB、263,659 条；
- `ChinaMax_Domain` 约 7.3 MB、111,566 条；
- 所有远程 rule-set 均以 `format: source` 加载。

同一配置使 SFM 系统扩展停止后仍保留约 1.3 GB RSS；移动端界面观察到约 460 MB。macOS 日志还出现过 `IPv4 routes are invalid`、`failed to add an IPv4 route` 和 RootHelper 通信错误，但同一次日志中隧道曾成功连接，因此这些警告必须在规则负载消除后独立复测，不能与规则内存问题混为一个根因。

本设计选择“轻量混合智能分流”：用小而确定的业务规则保护关键流量，用中国 IP 判断未分类流量，以代理作为无法判断时的安全终点。默认配置不再承担完整广告域名库，也不再依赖十万级中国域名分类表。

## 已确认的产品决策

1. 默认移除巨型广告规则；完整广告过滤成为独立可选增强包。
2. 删除默认 `ChinaMax_Domain`，以有硬上限的小型国内核心规则集替代。
3. 未分类目标解析后，中国 IP 直连，非中国 IP 代理；无法可靠判断时代理。
4. 国内游戏与海外游戏平台拆分：国内登录、更新、语音与 CDN 直连；海外平台进入可切换的代理策略组。
5. 五个客户端统一“分流含义”，但使用各自原生且高效的表达格式。
6. sing-box 生产配置只引用官方 core 编译的二进制 `.srs`，不得引用远程 source JSON。
7. 先发布测试版本并在真实设备灰度，验证后才更新 `current` 和 Sub-Store。

## 目标

- 消除 sing-box 因几十万条 source JSON 规则导致的启动内存暴涨。
- 保持抖音、国内视频、评论、图片/CDN、国内 App 与国内游戏稳定直连。
- 保持 AI、海外流媒体、Telegram、海外社交和海外游戏平台按业务意图走代理。
- 让未收录域名获得一致且保守的自动分流结果。
- 将共享语义、规则数据和客户端序列化分离，避免五个客户端各自决定分流含义。
- 为规则数量、下载体积、启动时间、运行内存和发布回退建立可执行的质量门禁。

## 非目标

- 不承诺“零数据、零规则下的完美分流”；域名、CDN、账号地区和业务意图无法只靠连接本身推断。
- 不实现失败连接的透明自动重放。TCP、QUIC、登录、支付和有副作用的请求不能被通用、安全地重放。
- 不使用 AI 或云服务实时猜测域名策略。
- 不上传用户访问记录，不以遥测自动扩充规则。
- 不依赖进程名作为跨平台核心规则；进程匹配能力在 iOS 与不同客户端之间不一致。
- 不修改代理节点凭据、协议参数或 Sub-Store 原始节点来源。

## 方案比较

### A. 轻量混合智能分流（采用）

小型确定规则负责国内核心、海外业务和游戏意图；中国 IP 负责剩余国内流量；最终代理负责未知与无法判断流量。它在内存、准确性、跨平台一致性和维护成本之间最平衡。

### B. 极简代理优先（拒绝）

除少数海外业务外全部代理。内存最低，但国内视频、CDN、下载和游戏容易变慢，不能接受。

### C. 完整列表加格式优化（拒绝）

保留 11 万中国域名和 26 万广告域名，只优化文件格式。它能减少 sing-box 的 JSON 解析成本，却保留了庞大更新、缓存、内存和误分类面，没有解决架构复杂度。

## 总体架构

系统由一个共享语义内核、一个确定性规则编译器和五个客户端适配器组成。

### 共享语义内核

共享层只声明“规则属于什么意图”和“意图对应什么策略”，不包含客户端语法。默认规则分为五层：

1. **基础安全层**：LAN、系统服务、DNS 劫持防护、少量恶意与隐私规则。
2. **国内核心层**：国内视频、评论、图片/CDN、社交、支付、地图、网盘、软件下载和关键国内服务。
3. **海外业务层**：AI、GitHub、YouTube、Netflix、Disney、Spotify、Telegram、海外社交等明确业务。
4. **游戏双层**：国内游戏直连；海外游戏平台进入独立策略组。
5. **未知判断层**：中国 IP 直连，其余与无法判断流量代理。

完整广告规则不属于默认共享层，而属于独立 `adblock-full` 可选包。

### 确定性规则编译器

编译器负责：

- 规范化域名、后缀、关键词、IPv4 CIDR 和 IPv6 CIDR；
- 删除完全重复及被更宽规则覆盖的条目；
- 检测同一目标被分配给互斥策略的冲突；
- 固定规则优先级并输出客户端无关的中间清单；
- 计算条数、字节数、来源与哈希；
- 超出预算、出现空文件或未解决冲突时失败关闭。

客户端适配器只能把已验证的中间清单转换为目标格式，不能自行改变策略或优先级。

### 客户端适配器

- **sing-box**：源 JSON 仅供审计和编译；生产配置只引用官方 sing-box core 生成的 `.srs`。未知域名通过显式解析和中国 IP rule-set 判断。
- **Surge**：使用原生 `GEOIP,CN,DIRECT`；大量纯域名集合使用 `DOMAIN-SET`，混合规则使用 `RULE-SET`。
- **Shadowrocket**：使用原生 `GEOIP,CN,DIRECT` 和兼容的域名/IP rule-set，保持 `FINAL` 为主代理策略。
- **Egern**：使用原生 GeoIP/ASN 与 YAML rule-set；未知域名判断不得被不恰当的 `no_resolve` 跳过。
- **Anywhere**：没有统一 Profile 输出，因此发布中国 IPv4/IPv6 CIDR 的 DIRECT `.arrs` 和业务 `.arrs`，并在部署检查中要求 Rule 模式与正确绑定。

## 默认规则顺序

所有客户端必须保持以下语义顺序：

1. 私有地址、局域网和本机服务 → `DIRECT`。
2. 显式拦截的安全威胁 → `REJECT`。
3. 用户自定义规则 → 用户指定策略。
4. 国内核心域名 → `DIRECT`。
5. 国内游戏登录、更新、语音和 CDN → `DIRECT`。
6. 明确海外业务 → 对应业务策略组。
7. 海外游戏平台 → `🌍 海外游戏` 策略组，默认代理并允许手动直连或选择游戏节点。
8. 已获得真实目标 IP 且属于中国网段 → `DIRECT`。
9. 其他、解析失败或无法判断 → `🚀 节点选择`。

国内规则必须先于笼统的游戏、媒体和最终代理规则。不得再使用一个默认代理的通用 `Game` 集合同时承载国内和海外游戏。

## 国内核心规则集

国内核心是 `ChinaMax_Domain` 的替代品，而不是缩小版广告或全量中国网站目录。它只保护误走代理会明显影响体验的关键生态：

- `.cn`；
- 抖音、今日头条及评论、图片、视频 CDN；
- 哔哩哔哩及视频、弹幕、评论 CDN；
- 腾讯视频、爱奇艺、优酷、芒果；
- 微信、QQ、微博、小红书；
- 常用支付、地图、网盘和国内软件下载；
- 国内游戏登录、更新、资源与语音服务。

默认预算为不超过 2,000 条。新增条目必须说明对应服务和误分流证据，不能仅因为域名看起来像国内站点就加入。

## DNS 与未知流量数据流

1. 客户端从 DNS 映射、TLS SNI、HTTP Host 或 QUIC 元数据中尽量恢复真实域名。
2. 国内核心域名使用国内可信 DNS 并直连。
3. 明确海外业务使用代理侧加密 DNS并进入对应代理策略。
4. 未命中域名规则时，用国内可信 DNS 获取真实 IP。
5. 中国 IP 直连；非中国 IP 代理。
6. 域名和真实 IP 均不可获得、DNS 失败或响应不可信时走代理。

嗅探只用于恢复域名和协议元数据，不承担“自动理解业务意图”的职责。DNS 规则、路由规则和 Fake IP 映射必须成套验证，避免域名在路由阶段只剩无法定位国家的 Fake IP。

## 规则下载与启动依赖

默认配置只内置几十条启动规则，用于 LAN、DNS、规则下载地址和最关键国内服务。其余规则远程加载。

规则下载使用不依赖远程规则的独立启动通道。该通道可以使用具体代理节点与 DIRECT 候选，但不能引用尚未初始化的业务规则，避免“启动需要规则、下载规则需要代理、选择代理又需要规则”的循环。

- 有有效缓存时，下载失败继续使用最后一次有效版本。
- 首次安装且下载失败时返回明确诊断，不写入空缓存。
- Profile 与规则资源独立更新；普通规则变化不要求重新导入节点订阅。
- 所有远程资源使用内容哈希和不可变快照支持回退。

## 资源预算与发布门禁

默认发布必须同时满足：

- 国内核心域名不超过 2,000 条；
- 默认全部规则不超过 25,000 条；
- 默认远程规则总下载体积不超过 5 MB；
- sing-box 生产配置没有 `format: source`，也不引用远程 `.json` rule-set；
- 广告增强包没有进入默认 Manifest；
- 所有引用目标、策略组、规则标签和文件均存在；
- 无空文件、未解决冲突、格式错误和非确定性生成差异。

任一门禁失败时停止发布并保留现有 `current`。

## 故障隔离与回退

项目生成两个 sing-box 测试入口：

- **最小诊断配置**：不加载远程业务规则，只验证节点、DNS、TUN、IPv4/IPv6 路由、VPN 权限和 RootHelper。
- **轻量正式配置**：加载本设计的默认二进制规则。

若最小配置失败，调查 TUN、IPv4 route、VPN 权限、系统扩展或 RootHelper。若最小配置成功而正式配置失败，调查 rule-set 下载、格式、缓存或资源预算。

每个客户端保留不可变旧版本、旧 Manifest 和恢复说明。客户端独立灰度与回退；一个客户端失败不得迫使其他客户端切换到未验证产物。

误分流通过客户端本地日志中的规则标签、目标域名、解析 IP 和最终策略定位。经过人工审核后才能更新国内核心；项目不采集或上传用户访问记录。

## 测试设计

### 共享语义测试

统一测试矩阵必须覆盖：

- 抖音视频、评论、图片 CDN → `DIRECT`；
- 哔哩哔哩视频、弹幕、评论 → `DIRECT`；
- 腾讯视频、爱奇艺、优酷、芒果 → `DIRECT`；
- 国内支付、地图、网盘和软件下载 → `DIRECT`；
- 国内游戏登录、更新、语音和 CDN → `DIRECT`；
- 海外游戏平台 → `🌍 海外游戏`；
- AI、Telegram、Netflix 等 → 对应代理策略；
- 未分类中国 IPv4/IPv6 → `DIRECT`；
- 未分类海外 IPv4/IPv6 → `🚀 节点选择`；
- 无法解析或无法判断 → `🚀 节点选择`。

每个客户端适配器必须针对同一语义用例生成等价结果。

### 格式与构建测试

- 验证规则顺序、重复、覆盖和互斥策略冲突。
- 验证国内核心、总规则数和下载字节预算。
- 验证所有策略组和规则资源引用。
- 验证默认产物不包含巨型广告规则。
- 使用官方 sing-box core 编译 `.srs` 并运行目标版本 `check`。
- 验证 `.srs` 非空、为二进制、版本受支持且哈希进入 Manifest。
- 验证 Surge、Shadowrocket、Egern 和 Anywhere 产物通过现有格式验证器。
- 验证重新构建逐字节一致，且密钥扫描不发现私有订阅 URL 或节点凭据。

### 真实设备验收

- VPN 在 30 秒内成功启动；
- 连续运行 5 分钟不自动退出；
- 加载规则造成的额外内存不超过 50 MB；
- 客户端显示总内存目标低于 200 MB；
- 停止 VPN 后规则内存应释放，不得长期保留约 1.3 GB；
- 通过规则命中日志和出口 IP 验证国内与海外测试用例；
- 不能仅以“网页能打开”作为通过标准。

## 灰度发布顺序

1. 生成独立测试版本，不覆盖 `current`。
2. 在 macOS SFM 运行最小诊断配置，隔离 TUN 与规则问题。
3. 在 macOS SFM 运行轻量正式配置，记录启动时间和内存。
4. 在 iPhone 和 iPad 测试启动、视频、评论、国内 App 与游戏。
5. 分别测试 Surge、Shadowrocket、Egern 和 Anywhere 的规则命中日志。
6. 每个客户端通过后独立更新测试通道。
7. 连续稳定运行后才更新 `current` 和对应 Sub-Store任务。
8. 发布后再次验证线上资源、Manifest、内存预算和旧版本回退。

## 完成标准

- 五个客户端对统一测试矩阵产生等价策略结果。
- 默认产物已移除巨型广告和 `ChinaMax_Domain`。
- 国内核心与游戏拆分保护已生效。
- sing-box 生产配置只使用二进制 `.srs`，不再出现 source JSON 内存暴涨路径。
- SFM 最小诊断与轻量正式配置都能明确区分 TUN 故障和规则故障。
- 真机启动、持续运行、内存和分流验收全部通过。
- `current` 仅在灰度成功后更新，失败可按客户端独立回退。

## 明确排除的后续想法

以下能力不属于本次默认设计，未来如需评估必须单独设计与批准：

- 自动上传访问历史并由服务器生成个人规则；
- 使用 AI 实时判断每个新域名；
- 在不同出站之间自动重放已经失败的业务请求；
- 默认重新启用完整广告或十万级中国域名表；
- 为追求客户端语法一致而放弃各客户端原生高效格式。
