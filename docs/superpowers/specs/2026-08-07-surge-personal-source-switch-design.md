# Surge 个人远程节点池切换设计

## 背景

Surge 配置目前可以通过 `policy-path` 使用 Sub-Store 生成的远程节点池。项目生成的节点名经过标准化，例如 `🇯🇵 节点名｜自建·U`；用户手动替换为个人 Surge 节点订阅后，节点名可能是 `🇯🇵Neburst1|DMIT-T1`。现有地区筛选表达式要求国旗后有空格，导致个人订阅中的节点无法进入“亚太自动”等分组。

## 目标

1. Surge 的地区自动组兼容标准化节点名和个人订阅的紧凑节点名。
2. 保留现有默认远程节点池行为，未配置个人链接时生成结果保持兼容。
3. 当私有参数提供个人链接时，在配置中同时生成一个独立的个人远程节点池，并提供可见的来源切换入口。
4. 个人链接只存在于私有 Sub-Store 文件操作参数和下载后的 Surge profile，不写入公开 GitHub 源码、示例或构建产物。
5. 默认自动组同时纳入两个远程池；节点选择组可以直接切换到来源选择组，用户无需手工替换 profile 文本。

## 非目标

- 不修改 Egern、sing-box、小火箭或 Anywhere 的输出。
- 不尝试改写个人订阅服务端返回的节点名或协议参数。
- 不把个人订阅内容复制到仓库，也不在公开日志中打印完整链接。
- 不为个人节点伪造 `｜自建` 等来源标签；来源专属分组只对项目标准化节点生效。

## 方案

### 选项与远程池

在 Surge profile 参数中新增可选 `personalPolicyUrl`。它与现有 `proxyPolicyUrl` 使用相同的安全 HTTPS URL 校验。任何一个 URL 存在时都进入远程模式，profile 的 `[Proxy]` 不嵌入节点传输详情。

远程池名称固定为：

- `📦 远程节点池`：现有默认 Sub-Store 输出。
- `🧩 个人节点池`：仅当 `personalPolicyUrl` 存在时输出。

两个远程池都设置 `update-interval=21600` 和 `hidden=1`。当个人池存在时新增：

```ini
🛠 节点来源 = select,📦 远程节点池,🧩 个人节点池
```

并把 `🛠 节点来源` 加入 `🚀 节点选择` 的候选项，使用户可以从主节点选择界面进入来源切换。

### 自动组包含策略

含有节点筛选器的共享策略组统一使用 Surge 的多来源包含语法：

```ini
include-other-group=📦 远程节点池,🧩 个人节点池
policy-regex-filter=...
```

实际输出按 Surge 转义规则转义逗号。只有存在的远程池才会出现在列表中；默认池单独使用时保留原始单来源语法。

### 地区筛选

`continentFilter` 从“国旗后必须有空格”改为“节点名以地区国旗开头”，以兼容：

- `🇯🇵 Tokyo｜机场·U`
- `🇯🇵Neburst1|DMIT-T1`

其他/未分类筛选同步按已知国旗前缀排除，避免紧凑命名误判。共享的非链式、协议能力和服务组保持原有语义。

### 校验与兼容

Surge profile validator 将 `include-other-group` 的值按逗号拆成多个引用，再执行引用存在性和环检测。旧的单来源 profile 和没有个人参数的 profile 必须继续通过原有测试。

## 私有 Sub-Store 配置

Surge 的三个 profile 文件（macOS、iPhone、iPad）继续使用默认 `proxyPolicyUrl`。在每个文件的 Script Operation 参数中增加 `personalPolicyUrl=<用户个人链接>`；该参数由 Sub-Store 私有 API 保存，公开生成器脚本只接受参数，不包含具体 token。节点输出文件 `surge-nodes` 不增加个人链接，避免把个人池误用于其他客户端。

## 验收标准

- 个人紧凑命名的日本、新加坡节点能被 `⚡ 亚太自动` 和 `🌏 亚太` 匹配。
- profile 同时包含两个隐藏远程池、一个来源切换组，并且 `🚀 节点选择` 可引用来源切换组。
- 没有个人参数时，profile 与现有默认远程模式结构一致。
- validator、Surge 单元测试、构建、fixture、密钥扫描全部通过。
- 私人链接不出现在 Git diff、构建产物、测试快照或公开 GitHub 文件中。
