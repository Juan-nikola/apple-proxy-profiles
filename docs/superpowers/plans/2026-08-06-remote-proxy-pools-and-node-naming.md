# 远程代理池、节点命名与 sing-box 1.14 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复 sing-box 最新测试版兼容性，统一节点短命名，并为 Surge 增加官方 `policy-path` 远程节点池，同时保留可回退的内嵌模式。

**Architecture:** 共享层继续负责来源识别、地区归类、名称生成和策略筛选。Surge 新增一个只输出策略行的私密 Sub-Store File Operator，Profile 通过 `policy-path` 引用它；Egern 沿用现有 `urls` 远程组；sing-box 不引入非官方 Provider，而是输出包含完整 outbounds 的远程 JSON，并按 `1.14.0-beta.7` 使用显式 HTTP client 和 rule-set 路由。

**Tech Stack:** Node.js 22、Node built-in test runner、ES modules、esbuild 0.28.1、Surge INI renderer、sing-box JSON renderer、GitHub Pages public artifact builder。

## Global Constraints

- 所有真实节点、订阅 Token、UUID、密码、私钥、节点 URL 和私密输出 URL 只能存在于用户的 Sub-Store 与设备中。
- 节点显示名固定采用 `地区 + 来源 + 简短名称`，示例为 `🇭🇰 自建 · Boil-HKT [UDP]`。
- Surge 覆盖 `macos`、`iphone`、`ipad`；sing-box 覆盖 `macos`、`iphone`、`ipad`、`android`、`openwrt`。
- sing-box 配置目标为官方 `1.14.0-beta.7`；生成结果不能包含 `geoip`、`geosite`、`download_detour` 或 `store_rdrc`。
- `proxyPolicyUrl` 只接受没有凭据、fragment 或控制字符的 HTTPS 绝对 URL。
- 不支持的节点协议或字段必须自动排除，并只输出不含节点值的聚合原因码。
- `proxyPolicyUrl` 缺失时 Surge 保留内嵌节点模式，已有旧 Sub-Store File 可以继续工作。
- 业务源码、测试和文档是修改入口；`dist/`、`examples/` 和 `public/` 中的生成文件只能由构建流程更新。
- 每个任务完成后运行该任务的定向测试并提交一个可回退的 commit。
